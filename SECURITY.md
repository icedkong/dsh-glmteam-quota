# Security policy

## Reporting a vulnerability

Please report security issues privately through GitHub's **Report a vulnerability** flow for [icedkong/dsh-glmteam-quota](https://github.com/icedkong/dsh-glmteam-quota/security/advisories/new), if enabled. If private reporting is unavailable, open an issue asking for a private contact; do not include credentials or tokens in a public issue.

## Credential handling

- Provider credentials are resolved and used by the local DSH Host; normalized quota results do not contain them.
- DeepSeek API-key quota eligibility uses the same validated endpoint resolver and launch-snapshot source as provider grouping. A provider ID alone cannot select an official probe. Invalid native overrides, unavailable endpoint metadata and relay destinations produce status-only rows before key resolution, network access or cached-balance lookup; one failed row does not abort unrelated providers. Native endpoint resolution never reads managed credentials or native grants, and account-wallet service queries retain their independent account-binding safeguards.
- GLM Coding Plan monitoring is selected only by the explicit official `/api/coding/paas/v4` route on `api.z.ai` or `open.bigmodel.cn`, or by a built-in Coding Plan route ID when no explicit base URL is available. Domestic Standard API `/api/paas/v4` is queried separately using Bearer auth at the fixed `open.bigmodel.cn/api/biz/account/query-customer-account-report` and `open.bigmodel.cn/api/biz/tokenAccounts/list/my` endpoints; package pagination is capped at 10 pages of 50 rows, and upstream account/order/token identifiers are discarded. International Standard API `/api/paas/v4` remains status-only; no credentials are sent to guessed endpoints.
- The optional OpenAI Admin Key is saved through the Harness credential service and sent only to fixed official OpenAI Costs and project API-key metadata endpoints over HTTPS. Key-name lookup is best effort and does not retain key secrets or owner metadata.
- The Codex quota adapter reads only the existing native `openai-codex` access grant; it does not read refresh tokens, CLI files or browser cookies, and does not perform inference or mutate the grant. Credits use the very same fixed usage GET and account-bound cache as quota windows: only a bounded decimal amount or allowlisted availability state is exposed, never the upstream body, identity, approximate-message arrays or reset-credit records. No purchase, reset redemption or automatic-reload operation is called; usage-credit data does not authorize inference or indicate an API cash balance.
- Codex login is built into this bundle: its own authenticated Fetch endpoints call the public DSH `authorization` service; no external OAuth UI plugin is required. The native SDK owns OAuth, PKCE, token exchange and credential persistence. This plugin does not import CLI credentials or copy/write grants, and missing native capability disables login without affecting read-only quotas.
- Login starts only after an explicit action. Mutations require same-origin/Host checks, a constant-time CSRF check and bounded JSON. Route/configuration, attempt IDs and callback state are rechecked; only validated official URLs and device challenges from this surface's own attempt are projected. Raw notices, errors, tokens and other surfaces' challenges are never returned.
- Cancel, expiry and disposal abort only the request owned by this surface, never a different native login. Cancellation cannot roll back a credential write already admitted by the SDK; stored-credential presence is separate from this attempt's successful completion.
- Do not paste API keys, Admin keys, OAuth links/codes or callback URLs into issues, chat transcripts, logs or screenshots.

## Model discovery

- The model editor starts discovery only on demand, via an authenticated Host route with same-origin and CSRF checks, bounded JSON, and limited concurrency. Listing requests are read-only and do not run inference or save settings.
- The plugin uses explicit listing contracts for known routes and a shared protocol transport for compatible custom routes. A stored key is used only for the saved endpoint and protocol; changing either needs an explicit one-shot key to query with credentials. Ambient references are limited to documented platform endpoints. Custom authorization headers and native OAuth grants are not replayed by model discovery.
- Live listing uses public HTTPS only, rejects redirects, and bounds time, pagination, and response size. Requests matching fixed, validated platform contracts use the DSH Host's outbound proxy configuration. Custom destinations instead require a direct connection with validated public DNS answers pinned to the connection; local/private targets and custom destinations reachable only through a proxy are not supported by this live path. Responses project only bounded model metadata and safe failure codes.
- Fallback uses DSH's catalog-only discovery when available. No endpoint or credential is included in that fallback request; a failed custom listing is not reissued through DSH's network path. Cancellation and a successful empty list do not trigger fallback. Results are draft candidates, not proof of account access or inference compatibility.

## Company-rule updates

- Online provider rules are display metadata, not credential or quota-destination authorization. They never alter the fixed endpoint allowlists used by quota adapters.
- The Host requests one fixed HTTPS JSON URL in the plugin's repository with redirects refused, no authentication/cookies, no user-supplied URLs, domains or query parameters. The source still receives ordinary network metadata such as the Host's IP address. No RDAP/DNS/website ownership lookup is performed.
- Downloads are limited to 128 KiB and an eight-second total deadline. Lazy daily checks, a shared one-minute refresh cooldown, and a single in-flight request limit traffic.
- Strict schema/PSL-domain checks, unambiguous family assignments, monotonic revisions and same-revision content protection prevent malformed/rollback updates from replacing valid data. Names are plain text; icon IDs reference bundled marks only. Reference URLs are data, never automatically fetched.
- Domain-root, restricted service-suffix and exact-host selectors have distinct semantics. Shared cloud-hosting namespaces are not automatically provider-owned model services: Vercel AI Gateway, the recorded AWS Bedrock regions and Alibaba MAAS hosts use exact-host rules, Azure uses documented service suffixes. Cross-provider overlap is rejected. Future unrecognized hosts remain local pending coverage, not inferred brands.
- The development catalog snapshot reads only shipped public provider/model metadata, never profile data or credential values. Runtime hostname coverage is computed locally and is not a report sent to the publisher. Snapshot coverage is tied to its recorded DSH/pi-ai versions and does not certify live or future endpoints.
- Native DeepSeek normalization recognizes only the standard account/API-key provider IDs paired with their standard namespaces and whole-section paths. It follows configured `baseURL`, then the existing launch snapshot's `DEEPSEEK_BASE_URL` (or the SDK-equivalent lazy, single-key process lookup only when no snapshot exists), then the verified Messages default; explicit blank/invalid or unavailable endpoint information stays unclassified. This lookup never reads native grants or managed credentials. Namespace aliases are not inferred, and directory shape matching is a compatibility filter, not package-owner attestation. Only route identity, the sanitized hostname and an optional authentication-presence bit reach the browser.
- Model-catalog grouping is a separate display hint, emitted only for matching DSH/pi-ai versions and an unchanged built-in route with no effective route endpoint or endpoint environment variables. A known compatible subset of stock models is allowed; an unrecognized model or transport override disables the hint. The hint never populates the actual endpoint or authorizes inference, discovery, credentials, or quota requests.
- Provider sorting combines exact user-setting paths (a root path requires a nonempty user object) with public configured-credential or stored-authentication presence. Native status uses only credential descriptors or the account service's safe `getState()` projection; that service may internally validate its grant, but this plugin never accesses its payload or forwards attempts, authorization links, tokens, masked values or record metadata through the route-host endpoint. Presence reads are bounded, deduplicated and capped at 256; errors preserve hostnames and existing saved settings. Flags are bound to full route identity, do not enable editing or quota requests, and are not proof of server-valid authorization. Defaults and adapter activity alone never promote a provider.
- Provider search runs entirely in the browser over provider display labels and sanitized hostnames or public rule selectors. It does not transmit queries, inspect credential references or index URL query strings and unrelated profile fields.
- Supplemental brand assets are pinned, licensed local SVG path data. The build validator accepts only bounded path geometry, a numeric viewBox, optional hex color and an enum fill rule; it rejects markup, arbitrary attributes and image URLs. Browser data excludes provenance URLs and never evaluates SVG/XML. Trademarks remain with their owners; product marks do not assert a different corporate identity.
- The publisher reviews ownership evidence; structural validation is not proof of ownership. Trust is rooted in the fixed GitHub repository and HTTPS, not a detached signature. Compromise of that repository could affect displayed provider labels, but cannot authorize credential disclosure.
- Optional DSH domain storage holds only validated public rules and timestamps. Invalid/unavailable persistence falls back safely to in-memory or bundled rules; no profile/credential files are scanned or edited for caching. Browser refresh POSTs require CSRF, and the shared agent operation never returns its token.

## Supported version

Versions 0.7.3, 0.7.4 and 0.7.5 declare DSH `>=0.2.2-rc.1 <0.2.3-0`, excluding 0.2.3 prereleases. Desktop `0.2.2-rc.5` is the recommended SDK and public-catalog baseline. Tests cover endpoint and credential isolation, model listing and fallback, and route metadata; rc.1–rc.4 have not each been re-tested against every change.

The historical live runtime baseline remains v0.6.0 on Desktop `0.2.2-rc.1`; MiniMax China M Plan quota reporting passed live-account acceptance later. Current source/fixture tests are not a new real-account end-to-end certification for every provider. Codex Credits, domestic GLM Standard API and OpenCode Go retain their documented Preview status. Please include the DSH and plugin versions in a report, but never attach credentials or raw authorization data.
